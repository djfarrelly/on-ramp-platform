# Prototype decisions — November 12, 2026

The user approved a database-first directory followed by conversational AI
discovery experiments. Source extracts in `context/` remain unchanged. This
file and `AGENTS.md` record the current implementation decisions.

## Keep the selected stack; build locally first

TanStack Start + React SSR, Cloudflare Workers/Vite, Hyperdrive, PostgreSQL and
Drizzle are implemented. Docker PostgreSQL 17 is a local development origin,
not a replacement production vendor. No PlanetScale or Cloudflare resources
are provisioned until the owner sets up the development database and binding.
We use the existing checkout and direct Wrangler deployment rather than Sites
hosting because the specified Hyperdrive/TCP database architecture is explicit.

The 29 domain tables are translated together in `src/db/schema/index.ts` to
keep the baseline reviewable. They can be split by domain as services grow.
The directory and bounded ingestion pass have application behavior. There is no
raw database admin UI.

## Small, explicit RPC methods

Named, versioned methods replace the REST examples. HTTP, SSR adapters and
future tools share services and Zod contracts. Neither the page components nor
the model own filtering, publication checks or SQL. Public methods return an
allowlist of fields; CRM IDs, contacts, provenance and internal metadata are
not exposed.

## Deliberate schema completions

`0000` is generated by Drizzle from the supplied 29-table model with these
documented constraint additions; `0001` supplies PostgreSQL-specific behavior:

- Composite primary keys on join tables prevent duplicate assignments.
- Partial unique indexes permit at most one primary lane per entity. A future
  publish service must also require at least one primary lane before publishing.
- Case-insensitive canonical slug uniqueness for organizations, programs and
  events. Pending replacement rows with `supersedes_id` may share the live slug.
  Approval should update the canonical record in place, preserving its ID and
  URL, then archive the proposal. No proposal is publicly visible.
- Published slugs become immutable. Archived, previously published records also
  retain their URLs. Services never derive slugs from a changing title.
- All declared foreign keys are indexed. Search vectors are GIN indexed;
  `pg_trgm` indexes support fuzzy names and organization aliases.
- Weighted search vectors are maintained by triggers on organizations,
  offerings and events. Tag/alias relations are searched separately; they are
  not falsely represented as generated columns referencing other tables.
- `updated_at` triggers are installed on the source tables that have the column.
- A published organization cannot reference a logo without nonempty alt text,
  and a referenced public logo cannot lose its alt text. Future public image
  surfaces must extend this enforcement before using assets.
- `tracking_events.id` uses a bigint identity rather than an ungenerated bigint.
- Case-insensitive email uniqueness on `users` supplements the source constraint.
- The events date index is scoped to published status; upcoming-date conditions
  belong in queries, because PostgreSQL index predicates cannot use `now()`.

The generated foreign keys use immediate checks. Any operation involving the
source's circular references must insert the nullable side first and link it
afterward within the transaction, as the seed does. Deferred FK behavior from
the DBML export has not been reproduced; add it in a migration if a future
workflow requires it.

Migrations are applied explicitly and never edited after application. Keep
`pg_trgm` and raw trigger SQL in versioned custom migrations when adding schema
changes; Drizzle's declarative schema does not represent those triggers.

## Discovery experiments

The original deterministic-only restriction is revised with user authorization.
The current bounded coordinator combines deterministic selections, intent
extraction and controlled search refinement. Future experiments can compare
model-selected recommendations against the same data and persona cases.
Use the same directory data and persona cases across approaches. Start with
one read-only tool and a small search budget. Validate selected IDs against
returned candidates and source cards/URLs from the database.

Keep transcripts ephemeral initially. Structured preferences and necessary
result facts can use an additive migration once the experiment shape is clear.
Do not reuse `routing_results.explanation` to suggest that a model-generated
reason was a deterministic rule evaluation. Record strategy/prompt/model
versions when persistence is added. Keep prompt/response payloads out of AI
Gateway, Sentry and application logs; model-provider retention also needs
configuration. Model calls use AI Gateway with infrastructure spend caps.

## Remaining work

Live model evaluation and model-selected recommendations; Better Auth tables and OTP; partner self-service;
full admin screens; Mapbox; broader inventory import; scheduled ingestion and
referral workflows; consent and retention enforcement before
collecting PII; reporting; privacy-safe analytics/Sentry. No live PII is
collected by this increment. Final taxonomy and referral confirmation behavior
remain product decisions. Manual screen-reader review remains outstanding.

The hybrid conversational workspace is implemented at `/discover`: four
starting buttons, a persistent composer, prior card sets and
service-owned multiple-choice questions. Typed choices map directly to filters;
freeform messages use a Gateway model or the readable baseline. The turn
coordinator plans, searches, optionally broadens only the topic, and selects the
next question. Each turn is bounded to one model request and two searches.
Requested and effective filters stay separate; changing hard preferences is
explicit. Optional answers are tracked so “anywhere” and “any format” are not
asked again. Eight exchanges remain in UI memory, while requests contain only
the latest event and structured state. No persistence migration was needed.
Model-generated recommendation prose and unbounded agent loops remain deferred.
See [discovery](discovery.md) for setup, the low-cost default model and limits.

## Local editorial review

The local editorial review increment is implemented at `/review`. The user
explicitly approved unauthenticated access for this prototype. A separate pair
of `review.*` RPC methods is enabled only for development builds on loopback
hosts, requires same-origin JSON requests, and records the existing local
reviewer audit identity. The production page and endpoints return 404. Original
token-protected ingestion administration and public LLM tools remain separate.
The UI reads a purpose-built proposal view and reuses the existing publication
service, including parent-first approval and optimistic timestamp checks. No
schema change, new authentication vendor or automatic approval was added.
See [local review](review.md).

## Core data and optional test fixtures

Normal initialization now seeds only the four core lanes. Fictional directory
data moved to `tests/fixtures/directory.ts` behind explicit demo seed/cleanup
commands. The original lane IDs remain stable because imported real records
reference them. Demo cleanup deletes only known fixture identities in a
transaction, preserves shared taxonomy, and aborts on unexpected foreign-key
dependencies. Browser tests now create/use a dedicated `_test` database and
server instead of seeding or reusing the working application database. No
migration is needed for this separation; existing fictional rows are removed by
the explicit cleanup command.

## Bounded ingestion pass

Migration `0002` adds source identities and content hashes to offerings, hashes
to events, per-run configuration/mode/diagnostics, a source-policy review note,
and unique indexes for canonical/proposed identities and active source runs.
This extends the source model rather than adding a parallel review table.

The first four sources use public JSON or database-stored DOM rules. Both
deterministic and optional LLM extraction create the same typed proposals.
Local CLI runs store raw evidence in ignored files; the Worker adapter uses R2
and a Cloudflare Workflow. Only explicit review publishes content. Published
record IDs and URLs survive source changes. No cron or remote resources are
provisioned. The public directory and private ingestion RPC registries remain
separate. See `docs/ingestion.md` for all commands and deployment prerequisites.

The second batch reuses the same database-configured HTML extractor: WCC,
Innovate Marquette and Michigan SBDC provide program pages; CAMW provides
discoverable event detail pages with machine-readable ISO dates and offsets.
No schema, vendor or dependency changes are needed. TechTown's selectors are
prepared but its source is disabled pending permission because its published
terms prohibit automated scripts. CAMW replaces it in the live batch. Startup
defaults preserve the original source IDs and do not overwrite policy notes or
edited selectors. Structural fixture tests cover content isolation, required
fields, bounded collection, review status, date offsets and idempotent reruns.

## Neutral UI baseline — November 18, 2026

User-approved simplification: shared presentation primitives now come from
shadcn/ui (Radix/New York) with Tailwind CSS v4, neutral theme tokens and system
fonts. Public pages, discovery and local review compose these primitives; the
previous lane palettes, bespoke control/card styles, SVG illustrations and chat
animations were removed. Product layouts and chat scroll/focus behavior remain
local composition concerns. Native selects preserve GET-form and browser control
behavior, including directory access without JavaScript. No service, transport,
database or review authorization behavior changes. Future design work should
update the shared theme/primitives rather than recreate per-page components.

Preset `b2NMmadS1I` replaces the initial neutral/New York presentation with

## Tagging pilot and review — November 19, 2026

The first classification vocabulary has 45 explicit, stable tag identities in
six groups. AI and data are separate topics; other broad support-type trade-offs
remain accepted by the user. Runtime definitions and Zod contracts are shared,
while classification, sample selection, evidence checks and decisions live in
`src/services/tagging/`. The AI SDK and provider adapters live in `src/server/`.
No model receives database access or a mutation tool.

Three additive tables record tagging runs, proposals and normalized suggestions.
Proposals have explicit nullable organization/offering/event foreign keys with a
one-entity check. Canonical assignments still use the original three tag joins.
Approval is additive and individual, preserves existing tags, checks listing and
tag-set fingerprints, and is invoked atomically with listing publication by the unified review flow.
Content edits retain only grounded selections in a fresh audited snapshot. Source configurations and existing editorial decisions are not
changed by classification.

The final user-approved flow puts tagging before human review in ingestion.
`/review` shows only records with current non-empty usable tags; a single decision
approves content/tags and publishes, with both timestamps checked. There is no
separate tag-review page. Low-level `tagging.*` methods remain development/loopback
only with same-origin JSON and an active staff identity. Production returns 404.
This exception does not grant remote staff access or add public discovery tools.

Vercel AI SDK is an OSS dependency, not a new hosted service. Its OpenAI adapter
uses the user's own credits through Cloudflare BYOK by default; Cloudflare-hosted
models use the compatible adapter. Business services consume provider-neutral
ports. On November 19 the user explicitly authorized one direct OpenAI pilot of
55 records because Gateway administration was unavailable. The CLI-only opt-in
requires the local `onramp` database, is recorded in the model identity and was
not enabled for HTTP or production. Gateway routing and Gateway spend caps
remain the default for subsequent model work.
